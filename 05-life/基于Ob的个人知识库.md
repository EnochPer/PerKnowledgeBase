## 三、逐环节的工具链 + 工作流

### 环节 1：信息源 → 论文/项目捕获

- **论文 PDF**：用 **Obsidian + Annotator 插件** 或 **Zotero + Obsidian 联动**。
  - 推荐 **Zotero**（管理论文元数据 + PDF）+ `Zotero Integration` 插件，一键把论文信息导入 Obsidian 建笔记。
- **网页/公众号文章**：用 **Obsidian Web Clipper**（官方出的浏览器插件）一键剪藏成 Markdown 进 `00-Inbox`。

### 环节 2：论文翻译 + 批注

这是你需求里很重的一块，给你两条路：

- **PDF 上直接批注**：Zotero 内置 PDF 阅读器划线批注，批注可同步回 Obsidian。
- **翻译 + 结构化笔记**（推荐）：
  - 用 **Copilot for Obsidian** 或 **Text Generator** 插件，预设一个 Prompt 模板：
    > "将以下论文段落翻译成中文，保留专业术语英文原文，并在末尾用一句话总结这段的核心观点"
  - 选中英文 → 一键生成中文翻译 + 批注，直接写进 `翻译批注.md`。
  - 中文润色能力上，接 **Claude** 效果最好。

### 环节 3：GitHub 项目体验 + 代码注释

这块是 Obsidian 和 VSCode 的**协同关键点**：

- **VSCode 里**：用 AI 编程插件（**Cline / Continue / Copilot**）给核心代码加注释和文档说明——这是你已有的工作流，保持。
- **沉淀到 Obsidian**：代码本身留在 Git 项目里，但"算法解读、为什么这么写、踩的坑"这类**理解性内容**写进 `02-Projects/某项目/核心算法解读.md`。
- **关键技巧**：在 Obsidian 笔记里用相对链接指向你本地代码文件，或贴关键代码片段 + 解读。**代码归代码库，理解归知识库**，分工明确。

### 环节 4：工作问题解决 → 方案文档

- 用 `99-Templates/` 里建一个**问题解决模板**，固定结构：

  ```markdown
  ## 问题现象
  ## 环境信息（平台/版本）
  ## 排查过程
  ## 根因
  ## 解决方案（含操作步骤）
  ## 复盘/延伸
  ```

- 遇到问题随手按模板填，存进 `03-WorkLog/对应分类/`。
- 这类文档积累久了就是你的**个人故障知识库**，配合 AI 语义搜索，下次遇到类似问题一搜即得——对你天天踩交叉编译/QoS/FPE 坑的工作来说，价值极大。

### 环节 5：AI 对话沉淀（最容易被忽略的金矿）

你提到"穿插大量与 AI 对话学习"——这些对话其实是你思考过程的高质量记录，但通常聊完就丢了。建议：

- 把有价值的对话，**提炼后**存进 `04-AIChat/`（不是全文复制，而是提炼结论 + 关键代码 + 你的理解）。
- 可以用 Copilot 帮你做这步：把对话粘进去，让它"总结成一篇结构化笔记"。

### 环节 6：输出到飞书

- Obsidian 笔记整理成熟后，需要对外/协作分享时，**复制 Markdown 粘贴进飞书**（飞书文档支持 Markdown 粘贴，格式基本能保留）。
- 关键原则：**飞书是输出端，不是存储端**。源头永远在你自己的 Obsidian 库里。换工作时飞书里的丢了无所谓，主库一行不丢。
