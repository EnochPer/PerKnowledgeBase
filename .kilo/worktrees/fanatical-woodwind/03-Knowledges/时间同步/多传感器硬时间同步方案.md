
# 机器人底盘时间硬同步方案与操作步骤

这套配置的时间体系本质是**"GNSS 做唯一绝对时基，硬件边沿对齐 + 硬件时间戳打标，主机做时基分发枢纽"**。下面按"方案架构 → 各传感器落地方式 → 可执行操作步骤 → 精度与风险"展开。

---

## 一、总体时间架构：三层

**第 1 层：绝对时间源（双频 GNSS/RTK 模组）**
整个系统只有这一个绝对基准（UTC）。它输出两路关键信号，缺一不可：

| 信号          | 物理形式                            | 作用                                     | 精度                            |
| ------------- | ----------------------------------- | ---------------------------------------- | ------------------------------- |
| **PPS** | 每秒一个上升沿（BNC/GPIO）          | **相位基准**——"告诉你就在此刻"   | ns 级抖动                       |
| **TOD** | UART 输出的 NMEA（GPRMC/ZDA/GPGGA） | **命名基准**——"告诉你这是哪一秒" | 报文本身只有 ms 级，靠 PPS 校正 |

一句话：**TOD 说"现在几点"，PPS 说"就是现在"**。RTK 1Hz 定位解算与 PPS 同源，所以位姿和时间天然对齐。

**第 2 层：时间分发（同步板 + 主机）**
PPS+TOD 进入同步分发板（MCU/FPGA）或直接进主机：

- 主机侧：PPS → `/dev/pps0` → chrony 纪律系统时钟；
- 分发侧：由同一 PPS 相位锁定，扇出 **LiDAR 同步口、相机触发脉冲、IMU SYNC**；
- 主机同时作为 **PTP Grandmaster**，向外提供 PTP / NTP / PPS+TOD 授时。

**第 3 层：时间消费者**
LiDAR / 相机 / IMU / 主机 / 下游设备，全部以主机/同步板时钟为同一时基。

## 二、各传感器的硬同步方式（核心）

### 1) 激光雷达（32 线等效、20 万点/s）

两种可行路径，**推荐前者**：

- **方案 A：PPS + NMEA 直连同步口（主流）**
  雷达内部用 PPS 上升沿复位每秒计数器，从 NMEA 读 UTC，给每帧/每个点块打 UTC 时间戳。这是绝大多数国产雷达（禾赛/速腾等）的"GPS/PPS 同步模式"。
- **方案 B：PTP 从时钟**
  网线即同步线，雷达内部时钟被 Grandmaster 纪律，帧自带硬件时间戳。布线更省，但要确认雷达固件支持 1588。

> 关键：驱动必须正确解析**帧头 UTC + 点级角度/时间偏移**，而不是把"驱动收到包的时刻"当时间戳——软件打戳直接毁掉 20μs 指标。

### 2) 工业相机（1080P + 内置 IMU）

- **外部硬件触发（Trigger Mode）**：同步板产生与 PPS **相位锁定**的周期脉冲（如 30Hz），相机每收一个触发曝光一次，并在 Line0/Latch 上锁存硬件时间戳。**必须全局快门**，否则卷帘逐行曝光，曝光时刻没有唯一值。
- **或 GigE Vision + PTP**：相机内部时钟同步到主时钟，每帧带硬件时间戳，无需额外触发线。
- 相机内置 IMU 时，注意让 **曝光同步事件与 IMU 采样同源**，否则视觉-惯性融合会引入固定偏移。

### 3) IMU

- 首选**硬件 SYNC 输入**：用 PPS/触发脉冲复位或触发 IMU 采样，保证采样时刻对齐整秒；
- 或**标记（marker）方式**：IMU 检测到 PPS 边沿即在数据流中插入标记，事后对齐。
- IMU 采样率 200Hz~1kHz，**1Hz 的 PPS 只能做锚点**，两次 PPS 之间必须用 IMU 内部时钟插值，并估计、补偿晶振漂移（温漂）。

### 4) 主机（RK3588S）

- PPS 进内核（`pps-gpio` 或 `ldattach` 串口 PPS）→ `/dev/pps0` → chrony 锁 UTC；
- linuxptp 做 Grandmaster，网卡需支持 **SO_TIMESTAMPING 硬件时间戳**（片上 GMAC 若支持 1588 可直接用，否则外挂带 PHC 的 PCIe 网卡）；
- ROS 2 侧：`header.stamp` 一律取**传感器硬件时间戳**，系统时钟由 PPS 纪律后作为统一 CLOCK_REALTIME。

## 三、操作步骤（可执行）

### 阶段 0 · 硬件安装

- 有源天线装车顶无遮挡处，馈线 50Ω 匹配、长度尽量短，**远离 4G/5G 天线和电机线**（避免共模干扰破坏 PPS 边沿）。
- 接线：GNSS→PPS（GPIO/BNC）、GNSS→TOD（UART）、同步板→雷达同步口 / 相机 Trigger / IMU SYNC。
- 上电顺序：先 GNSS 与同步板，后各传感器。

### 阶段 1 · GNSS 时间源配置与验证

```bash
# 读 NMEA，确认定位与时间字段
sudo gpsmon /dev/ttyS1        # 或 cgps -s / cat NMEA
```

- 确认 fix 类型（RTK Fixed/Float/Single）与 NMEA 中时间有效性标志；
- 示波器测 PPS 引脚：周期 1Hz、上升沿陡峭、脉宽符合配置（典型 100ms），**测各支路 PPS 相位一致**；
- 配置模组：PPS enable、TOD 语句（GPRMC/ZDA）、波特率（如 115200）、UTC/闰秒处理。

### 阶段 2 · 主机时钟纪律

```bash
# 内核：CONFIG_PPS / CONFIG_PPS_CLIENT_GPIO 或 LDISC
modprobe pps_core
ldattach PPS /dev/ttyS1        # 串口 PPS；GPIO 方案用 pps-gpio
ls /dev/pps0
ppstest /dev/pps0              # 验证每秒边沿

# chrony：NMEA + PPS 双参考
# /etc/chrony.conf:
#   refclock SHM 0 refid NMEA noselect
#   refclock PPS /dev/pps0 refid PPS lock NMEA prefer
chronyc sources -v
chronyc tracking               # 看 System time / Last offset
```

目标是系统时钟锁定到 UTC，offset 稳定在亚微秒~微秒级。

### 阶段 3 · 建立 PTP 主时钟

```bash
sudo ptp4l -i eth0 -f gPTP.cfg -m
sudo phc2sys -a -r -m            # PHC 与系统时钟对齐
# 若网卡/PHC 可直连 GNSS PPS，用硬件喂时：
sudo ts2phc -f gPTP.cfg -s /dev/pps0 -m
sudo pmc -u -b 0 'GET PORT_DATA_SET'   # 查询从时钟 offset
```

### 阶段 4 · 传感器侧配置

- **雷达**：厂商工具切到 GPS/PPS 同步模式，时区设 UTC，验证时间戳单调递增且 1s 处对齐 PPS；
- **相机**：切 Trigger Mode，触发频率与 PPS 相位对齐，开启硬件时间戳，验帧戳；
- **IMU**：配置外部 SYNC 输入，设定采样率，记录同步事件计数。

### 阶段 5 · 系统级验证与标定

- **单路合法性**：检查各路时间戳单调、无回退、无跳变；
- **交叉验证**：旋转台/摆动靶标，同时采 LiDAR+相机+IMU，看时间戳是否落在同一时刻；
- **固有时延标定**：分别标定"触发→曝光→读出"和"雷达扫描→点输出"的**固定延迟**，写入驱动做补偿；
- **统计误差**：多次 PPS 下统计各路时间戳标准差，确认 ≤20μs（含最长尾延迟）。

### 阶段 6 · ROS 2 集成（你的强项区）

- 统一时钟源：所有节点读同一系统时钟，`use_sim_time=false`；
- 时间戳**透传硬件时间**，不用接收时刻；
- 时间敏感话题用 `SensorDataQoS`（best effort / KeepLast 小队列）；
- 用 `message_filters::sync_policies::ApproximateTime` 做跨模态对齐，队列深度按最慢传感器周期设；
- 校验所有节点时钟同源，避免个别容器/节点用了独立时钟域。

### 阶段 7 · 运维与失效处理

- 冷启动无 GNSS：用 RTC 保底，精度降级；定位后由 chrony 平滑收敛；
- 进入隧道/室内失去卫星：进入 **holdover**，靠 TCXO/OCXO 维持，记录偏移；
- 监控：chrony offset、PTP slave offset、PPS 丢失告警、晶振温漂。

## 四、20μs 指标怎么保证 / 误差预算

软件打时间戳（内核 soft timestamp）抖动动辄几十 μs 到 ms，**根本摸不到 20μs**。达标必须三件套：**硬件边沿对齐 + 硬件时间戳 + 固定延迟补偿**。误差主要来源：

| 环节                    | 量级                 | 应对                     |
| ----------------------- | -------------------- | ------------------------ |
| GNSS PPS 固有精度       | ns                   | 无                       |
| 线缆/扇出 skew          | ns~μs               | 等长线、同一同步板扇出   |
| PTP 网络同步            | 亚 μs（硬件戳）     | 硬件时间戳 + gPTP        |
| 传感器内部采样/计数粒度 | **通常是大头** | 提高内部采样率、点级插值 |
| 触发→曝光/扫描延迟     | 固定值               | 标定后补偿               |
| 晶振温漂（两次 PPS 间） | 依赖器件             | OCXO/温补                |

**结论**：系统的同步精度由"最差的一环"决定——往往是 IMU 采样粒度或相机曝光时刻，而不是 GNSS。所以手上有示波器时，最该测的是**各支路相对 PPS 的实际相位差**，而不是只看协议说支持。

## 五、几个容易踩的坑（结合你的嵌入式场景）

1. **PPS 进了但内核没识别**：ARM64 上 `pps-gpio` 设备树节点、GPIO 中断触发沿（rising）、`pps_core` 加载缺一不可，`dmesg | grep pps` 先确认。
2. **TOD 串口被 gpsd 抢占**：`ldattach` 和 gpsd 争同一个 tty 会导致 PPS 与 NMEA 对不上锁——按 `lock NMEA` 正确绑定。
3. **同步板固件里 PPS 边沿判定用软件轮询**：会引入抖动，必须用外部中断/定时器 capture。
4. **雷达"PPS 同步"与"PTP 同步"混用**：同一链路只能选一个主时钟源，别让网线和同步线打架。
5. **时间戳回退**：PTP 锁相瞬间或 GNSS 失锁重捕时会出现时间回跳，ROS 2 里会触发 `message_filters` 异常，建议在驱动层加单调性保护。
